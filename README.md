# Recipes

Ryan's recipe collection as a static, phone-first website: house recipes (Mexican, Oaxacan and more), Pakistani and
North Indian dishes from S. Abbas Raza's book, beans, and bean cooking guides. Served by GitHub Pages at
https://recipes.beansalad.org.

Features: the unfiltered home page lists recipes newest first, grouped by date added (recipes with no `added` date
come last); search across titles, ingredients and notes; tag filters (cuisine, course, protein, season) and collection
chips; a recipe view with a servings scaler, a collapsed "Ingredients List" button (closed by default, since the
ingredients already live in the steps), an As written / US / Metric unit toggle, cook mode (keeps the screen
awake where the browser allows it), step checkboxes, tap-to-start step timers, and a clean print layout. Favorites,
the "made it" log, personal notes and step checks live only in each visitor's browser (localStorage). There are no
accounts and no backend. The site works offline after the first visit (service worker).

## File layout

| Path | What it is |
| --- | --- |
| `index.html` | The whole app: markup, CSS and JS in one file. Loads `data/recipes.json`. |
| `data/recipes.json` | Generated by `build.py`. Never edit by hand. |
| `recipes/<collection>/<id>.json` | One source file per recipe. This is what you edit. The file name is the recipe's id and URL (`#/r/<id>`). |
| `collections.json` | The collections, in display order: `house`, `raza`, `beans`, `guides`. Raza's book conventions are shown on each Raza recipe. |
| `build.py` | `build` turns the source files into `data/recipes.json`. `import` syncs source files from the Google Drive archive. |
| `autotag.py` | Starting tags for newly imported recipes. Only used when a source file has no tags yet. |
| `sw.js` | Service worker: caches the app and data. Network first, cache fallback. |
| `manifest.webmanifest`, `icon-192.png`, `icon-512.png`, `favicon.png` | Home-screen install and browser icon. |
| `logo.png` | BeanSalad.org header logo (transparent PNG, 360 px wide). |
| `robots.txt` | Asks all search engines not to crawl the site. `index.html` also carries `<meta name="robots" content="noindex, nofollow">`. Keep both. |
| `CNAME`, `.nojekyll` | GitHub Pages custom domain, and no Jekyll processing. |

## Source file format

Recipes follow Ryan's Recipe Writing Standard: ingredients live inside the steps. Each step is a bold action line
ending in a colon, then the exact ingredients that go in at that moment.

```json
{
 "title": "Pickled Red Onions",
 "collection": "house",
 "section": "Salsas & Condiments",
 "sort": 18,
 "source": {"text": "Ryan's own", "url": "optional link"},
 "makes": "4 servings",
 "added": "2026-11-22",
 "origin": "optional: where the recipe came from",
 "description": "optional short description",
 "beans": "optional, bean recipes only: which beans",
 "tags": {"cuisine": ["Mexican"], "course": ["Condiment"], "protein": ["Vegetarian"], "season": ["Any"]},
 "prep_min": null,
 "cook_min": null,
 "steps": [
  {"action": "Simmer until the sugar dissolves, 2 min:", "items": ["1 cup water", "½ cup cider vinegar (120 ml)", {"text": "1 Tbsp sugar", "sub": ["Honey works too"]}]},
  {"text": "A plain step with no ingredient list."},
  {"action": "Options! Add if desired:", "items": ["1 jalapeño, sliced"]},
  {"action": "Serve with:", "items": ["Tacos"]}
 ],
 "notes": [{"d": "2026-11-22", "kind": "Upload", "text": "Notes in Ryan's words"}],
 "edits": ["Editor notes: fixes, assumptions and gaps"],
 "hidden": false
}
```

Rules that matter to the build:
- Write each ingredient as `quantity unit item`, for example `1½ lb ground turkey` or `2 to 3 Tbsp Creole seasoning`.
  `build.py` splits it into `qty`, `qty_max`, `unit` and `item` so it can be scaled and converted. Unicode fractions,
  `1 1/2`, decimals and ranges with "to" all parse. A leading "about" or "up to" is kept.
- A metric or US equivalent in parentheses right after the item name, like `1¾ lb stewing beef (800 g)` or
  `500 g pork steaks (about 1 lb)`, becomes the `alt` amount and is used by the unit toggle in place of a computed conversion.
- Items with no quantity ("Salt to taste") still list as ingredients. Items that refer back to earlier steps
  ("All above", "Reserved chile water"), items starting with `[`, and how-to lines are kept in the steps but left out
  of the ingredient list. The patterns are `REF_RE` and `NOTE_RE` in `build.py`.
- Steps whose action starts with "Options" or "Serve with" are grouped separately in the ingredient list.
- Times written in step text ("simmer 20 min") become tap-to-start timers. `°F` in step text converts to `°C` in Metric.
- `makes` starting with a number drives the servings scaler; otherwise the scaler uses multipliers (½×, 1×, 2×).
- `hidden: true` keeps a recipe in the repo but off the site. `sort` orders recipes within a collection.
- Tag groups are fixed: `cuisine`, `course`, `protein`, `season`. Values are free text; the filter chips are built from
  whatever values exist.

## Adding a recipe

Either way, finish with build, check, commit, push.

**A. Write the source file directly** (simplest for one recipe)
1. Create `recipes/<collection>/<id>.json` using the format above. Pick a short lowercase id with hyphens.
2. `python3 -I build.py build --expect N` where N is the new recipe count (it was 83 at launch, guides not counted).
   The build fails with a clear message on a missing field, bad date, unknown tag group or duplicate id.
3. Preview: `python3 -m http.server 8000` and open http://localhost:8000. Check the recipe on a narrow window.
4. Commit and push (see Deploy).

**B. Sync from the Google Drive archive** (when recipes were added to All Recipes, the Raza docx or Bean Recipes v2)

The Drive folder `My Drive/Hobbies/Food` holds the archive sources: `_recipes_source/data.js` (All Recipes),
`_recipes_source/data_raza.js` (Raza) and `BeansAndGas/_source/data.js` (Bean Recipes v2, whose `fundamentals` become
the Guides collection). Those files also generate the .docx files, so they stay the master copy.
1. Dump each data.js to JSON with Node, from the Food folder:
   ```
   node -e 'console.log(JSON.stringify(require("./_recipes_source/data.js")))' > house.json
   node -e 'console.log(JSON.stringify(require("./_recipes_source/data_raza.js")))' > raza.json
   node -e 'console.log(JSON.stringify(require("./BeansAndGas/_source/data.js")))' > beans.json
   ```
2. `python3 -I build.py import --house house.json --raza raza.json --beans beans.json` (any subset of the three).
   Recipes are matched by collection and title. Content is replaced from the archive; `tags`, `prep_min`, `cook_min`
   and `hidden` already in a source file are kept. New recipes get starting tags from `autotag.py`; review them.
   A recipe renamed in the archive comes in as a new file: delete the old one.
3. Continue with steps 2 to 4 of path A. Do not commit the JSON dumps.

## Deploy

GitHub Pages serves branch `main` from the repo root. Push with:
```
git -c push.negotiate=true push origin main
```
Pages rebuilds in a minute or two. Visitors get the new version on their next online visit (the service worker is
network first). If you change the list of shell files in `sw.js`, bump its `V` constant.

Custom domain: `CNAME` holds `recipes.beansalad.org`. DNS needs a CNAME record `recipes` pointing to
`banksbean.github.io`. In the repo's Settings, Pages: source "Deploy from a branch", branch `main`, folder `/ (root)`,
custom domain `recipes.beansalad.org`, then "Enforce HTTPS" once the certificate is issued.

- Tags were assigned by Claude at import (`autotag.py` plus manual overrides), not by Ryan. Edit them in the source files.
- No recipe has prep or cook times yet; `prep_min` and `cook_min` are null and the site hides them until set.
- 37 recipes have no `makes`, so they scale by multiplier only. 4 bean recipes have no source.
- Not yet in any archive, so not on the site: Xianglajiang (Google Doc), Pesto Ratios, Space Sludge (Sheets).
- The site is public but kept out of search engines (robots.txt plus noindex). The repo itself is public on github.com and can still show up in search.
- The site is public. The Raza recipes are a conversion of a copyrighted book, published at Ryan's direction.
